# Golang 日志库开发设计文档


## 一、项目概述

### 1.1 项目目标
开发一款轻量、高性能、可扩展的Golang日志库，支持多级别、多格式、多输出目标的日志记录能力，适配从开发调试到生产环境的全场景需求，同时提供兼容Go标准库`log`的接口，降低存量代码迁移成本。

### 1.2 版本演进路线
遵循渐进式开发策略，分阶段实现核心能力、功能增强、性能优化及生产级特性，具体版本规划如下：
- **v0.1.0**：基础可用版，实现核心日志输出能力
- **v0.2.0**：功能增强版，补充文件输出场景适配
- **v0.3.0**：性能优化版，提升高并发场景下的性能
- **v0.4.0**：生产级完善版，补充线上环境必备特性


## 二、总体设计

### 2.1 核心架构
日志库采用模块化设计，主要包含以下核心模块：
```
日志库核心
├── 配置模块（Config）：管理日志级别、输出格式、目标等配置
├── 日志级别模块（Level）：定义并管理日志级别及动态切换
├── 格式化模块（Formatter）：实现JSON/txt等格式序列化
├── 输出模块（Writer）：管理控制台、文件等输出目标
├── 并发控制模块（Sync）：保证多goroutine安全写入
├── 性能优化模块（Optimizer）：异步写入、无锁机制等
└── 扩展模块（Extension）：Hook、采样、网络输出等
```

### 2.2 核心流程
1. 初始化：加载配置（默认/代码/文件配置），初始化输出目标、格式化器
2. 日志写入：用户调用日志方法（Debug/Info等），检查级别是否启用
3. 日志处理：组装日志元信息（时间、级别、位置等），执行格式化
4. 输出分发：根据配置将格式化后的日志写入指定目标（控制台/文件/网络等）
5. 扩展处理：触发Hook（如Error级别告警）、执行采样等附加逻辑


## 三、模块详细设计

### 3.1 配置模块（Config）
#### 3.1.1 核心配置结构体
```go
type Config struct {
    Level         Level          // 日志级别（Debug/Info/Warn/Error/Fatal/Panic）
    Format        string         // 输出格式（"json"/"txt"）
    Outputs       []OutputConfig // 输出目标配置
    EnableCaller  bool           // 是否启用调用文件路径和行号
    EnableColor   bool           // 是否启用控制台彩色输出（仅txt格式）
    // v0.2.0+ 扩展字段
    GlobalFields  map[string]interface{} // 全局固定字段
    RotateConfig  RotateConfig          // 日志轮转配置
    // v0.3.0+ 扩展字段
    Async         bool                  // 是否启用异步写入
    BufferSize    int                   // 异步缓冲区大小
    // v0.4.0+ 扩展字段
    Sampling      SamplingConfig        // 采样配置
}

// 输出目标配置
type OutputConfig struct {
    Type     string // 输出类型（"console"/"file"/"tcp"/"udp"）
    FilePath string // 文件路径（仅file类型）
    Addr     string // 网络地址（仅tcp/udp类型）
}
```

#### 3.1.2 配置加载方式
- 代码动态配置：提供`SetLevel`、`SetFormat`等方法
- 配置文件加载（v0.2.0+）：支持从YAML/JSON文件解析配置


### 3.2 日志级别模块（Level）
#### 3.2.1 级别定义
```go
const (
    LevelDebug Level = iota // 0
    LevelInfo               // 1
    LevelWarn               // 2
    LevelError              // 3
    LevelFatal              // 4
    LevelPanic              // 5
)
```

#### 3.2.2 核心能力
- 级别比较：判断日志是否满足输出级别（如`LevelInfo`会过滤`LevelDebug`）
- 动态切换：支持通过代码（v0.1.0）或HTTP接口（v0.4.0）实时调整级别
- 字符串转换：提供`String()`方法，输出级别名称（如"INFO"）


### 3.3 格式化模块（Formatter）
#### 3.3.1 接口定义
```go
type Formatter interface {
    Format(entry *Entry) ([]byte, error)
}
```

#### 3.3.2 实现类
- **TxtFormatter**：文本格式，示例：
  ```
  2023-10-01 12:00:00 [INFO] main.go:10: this is a info log
  ```
- **JsonFormatter**：JSON格式，示例：
  ```json
  {"time":"2023-10-01T12:00:00Z","level":"INFO","msg":"this is a info log","file":"main.go","line":10}
  ```

#### 3.3.3 元信息支持
- 基础字段：`msg`、`level`、`time`（所有版本）
- 扩展字段：`file`、`line`（v0.1.0+），`goroutine_id`、`hostname`（v0.2.0+），`trace_id`、`request_id`（v0.2.0+，从context提取）


### 3.4 输出模块（Writer）
#### 3.4.1 接口定义
```go
type Writer interface {
    Write(p []byte) (n int, err error)
    Close() error
}
```

#### 3.4.2 实现类
- **ConsoleWriter**：输出到控制台（支持彩色输出）
- **FileWriter**：输出到本地文件（v0.1.0+）
- **RotatingFileWriter**：支持按大小/时间轮转的文件输出（v0.2.0+）
- **NetworkWriter**：输出到TCP/UDP目标（v0.4.0+）

#### 3.4.3 日志轮转逻辑（v0.2.0+）
- 按大小切割：单文件达到100MB时自动切割，保留最近5个文件
- 按时间切割：支持按天/小时轮转，按保留时长（如7天）清理过期文件
- 归档压缩：超期文件自动压缩为`.gz`格式


### 3.5 并发控制模块（Sync）
#### 3.5.1 v0.1.0 实现
采用`sync.Mutex`保证多goroutine写入时的线程安全，避免日志错乱。

#### 3.5.2 v0.3.0 优化
- 无锁设计：通过原子操作管理日志级别等轻量状态
- 异步写入：引入内存缓冲区（channel），后台协程批量写入，减少锁竞争
  ```go
  // 异步写入流程
  func (l *Logger) writeAsync(entry *Entry) {
      select {
      case l.buffer <- entry: // 写入缓冲区
      default:
          // 缓冲区满时降级处理（如同步写入）
          l.writeSync(entry)
      }
  }
  
  // 后台协程批量处理
  func (l *Logger) startWorker() {
      go func() {
          for entries := range l.bufferBatch {
              for _, e := range entries {
                  l.writer.Write(e.Formatted)
              }
          }
      }()
  }
  ```


### 3.6 扩展模块（Extension）
#### 3.6.1 Hook机制（v0.4.0+）
定义Hook接口，支持在特定级别日志输出时触发自定义逻辑（如告警）：
```go
type Hook interface {
    OnLog(entry *Entry) error
}

// 示例：Error级别钉钉告警Hook
type DingTalkHook struct {
    Webhook string
}

func (d *DingTalkHook) OnLog(entry *Entry) error {
    if entry.Level >= LevelError {
        // 发送告警到钉钉
    }
    return nil
}
```

#### 3.6.2 日志采样（v0.4.0+）
对Debug/Info等高频级别日志按比例采样，降低输出量：
```go
type SamplingConfig struct {
    DebugSampling float64 // Debug级别采样率（0.0-1.0）
    InfoSampling  float64 // Info级别采样率
}

// 采样逻辑
func (s *SamplingConfig) ShouldSample(level Level) bool {
    switch level {
    case LevelDebug:
        return rand.Float64() < s.DebugSampling
    case LevelInfo:
        return rand.Float64() < s.InfoSampling
    default:
        return true // Warn及以上级别不采样
    }
}
```


## 四、接口设计

### 4.1 核心日志接口
```go
type Logger interface {
    // 基础日志方法
    Debug(args ...interface{})
    Info(args ...interface{})
    Warn(args ...interface{})
    Error(args ...interface{})
    Fatal(args ...interface{}) // 输出后调用os.Exit(1)
    Panic(args ...interface{}) // 输出后触发panic
    
    // 格式化日志方法
    Debugf(format string, args ...interface{})
    Infof(format string, args ...interface{})
    Warnf(format string, args ...interface{})
    Errorf(format string, args ...interface{})
    Fatalf(format string, args ...interface{})
    Panicf(format string, args ...interface{})
    
    // 带context的日志方法（v0.2.0+）
    DebugCtx(ctx context.Context, args ...interface{})
    // ... 其他级别带ctx方法
}
```

### 4.2 兼容标准库接口
提供与`log`标准库兼容的接口，支持平滑迁移：
```go
func Println(v ...interface{}) {
    globalLogger.Info(v...)
}

func Printf(format string, v ...interface{}) {
    globalLogger.Infof(format, v...)
}

// 其他兼容方法（Fatal、Panic等）
```


## 五、版本迭代规划

### 5.1 v0.1.0 开发任务
1. 实现6个基础日志级别及动态配置
2. 开发Txt/JSON格式化器，包含核心元信息
3. 实现ConsoleWriter和基础FileWriter
4. 基于`sync.Mutex`实现并发安全
5. 支持基础类型格式化输出
6. 实现panic捕获及堆栈输出
7. 开发标准库`log`兼容接口

### 5.2 v0.2.0 开发任务
1. 增加全局自定义字段功能
2. 开发YAML/JSON配置文件解析模块
3. 实现RotatingFileWriter（大小/时间轮转）
4. 开发日志归档压缩功能
5. 增加goroutine ID、主机名元信息
6. 适配context提取链路字段

### 5.3 v0.3.0 开发任务
1. 替换互斥锁为无锁逻辑（原子操作）
2. 实现异步写入（缓冲区+后台协程）
3. 优化JSON序列化性能（减少反射、复用缓冲区）
4. 性能基准测试（对比同步/异步写入性能）

### 5.4 v0.4.0 开发任务
1. 实现Hook机制及告警示例（钉钉/邮件）
2. 开发HTTP接口动态调整日志级别
3. 实现日志采样功能
4. 开发TCP/UDP网络输出Writer
5. 完善写入失败降级策略（如控制台 fallback）


## 六、测试策略

1. **单元测试**：覆盖各模块核心逻辑（级别判断、格式化、输出等）
2. **并发测试**：模拟1000+ goroutine并发写入，验证日志完整性
3. **性能测试**：
   - 同步/异步写入QPS对比
   - 不同日志大小下的性能损耗
   - 内存分配统计（减少GC压力）
4. **场景测试**：
   - 日志轮转切割准确性
   - 配置热更新有效性
   - 异常场景降级可靠性（如磁盘满、网络中断）


## 七、总结
本日志库通过模块化设计实现了功能的可扩展性，从基础输出到生产级特性的渐进式开发路线，既保证了初期快速可用，又能满足高并发、高可靠性的线上需求。同时，兼容标准库接口降低了迁移成本，适合各类Golang项目集成使用。
